A senior API engineer treats the installed base as a permanent constraint: adding an enum value to a response is breaking for strict Codable/Moshi decoders, so the server gates `partially_refunded` on X-App-Version (or a capability header) and maps it to a chosen legacy value for old apps; new apps ship with an unknown-value fallback first. `total` is never removed or retyped — `total_amount` is added beside it — and they spot the real trap: CAD orders on apps that render `total` as dollars, handled with a minimum-version gate for Canadian users or similar. They measure version usage before any removal. A competent generalist recommends "versioning" or "additive changes" in general terms, often calls a new enum value backward compatible, and misses the currency display issue on old clients.
